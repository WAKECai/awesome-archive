# 操作与维护手册

本文档说明：本站（开源项目归档）**如何工作**、**日常如何新增/修改项目**、**如何发布上线**，以及**常见问题的处理**。

## 1. 站点是什么

一个纯静态的开源项目归档站点，部署在 GitHub Pages：

- 访问地址：<https://wakecai.github.io/awesome-archive/>
- 托管仓库：`WAKECai/awesome-archive`
- 技术栈：**Astro** 静态站点生成 + GitHub Actions 自动构建部署

### 核心设计：Markdown 是唯一真相源

```
archive/**/*.md   （你手写/维护的地方 —— 唯一真相源）
      │
      │  npm run build 时自动执行 scripts/build-data.mjs 解析
      ▼
src/data/archives.json   （自动生成的中间数据，❌ 绝不手改）
      │
      ▼
Astro 渲染成静态页面  →  dist/  →  GitHub Actions 推送到 GitHub Pages
```

> ⚠️ **铁律**：`src/data/archives.json` 是构建脚本自动生成的，**永远不要手动编辑**。
> 所有增删改都只改 `archive/` 下的 Markdown，然后重新构建。

## 2. 目录结构

```
awesome-archive/
├── archive/                    # 👈 你的内容区（唯一真相源）
│   ├── 01-foundations/         #    基础 / 教育
│   ├── 02-ai-skills/           #    AI 编程技能
│   ├── 03-ai-agents/           #    AI 智能体与应用
│   ├── 04-computer-vision/     #    计算机视觉
│   ├── 05-dev-tools/           #    开发工具与框架
│   ├── 06-apps/                #    应用与娱乐
│   ├── 07-websites/            #    资源与网站
│   └── _template.md            #    👈 新建项目时复制它
├── scripts/
│   └── build-data.mjs          # 解析 Markdown → JSON 的脚本
├── src/
│   ├── data/archives.json      # ⚠️ 自动生成，勿手改
│   └── pages/
│       ├── index.astro         # 首页（列表 + 搜索 + 标签筛选）
│       └── projects/[slug].astro  # 每个项目的详情页
├── astro.config.mjs            # Astro 配置（含远程图片白名单）
├── .github/workflows/deploy.yml  # 自动部署配置
└── package.json                # 命令入口
```

## 3. 命令速查

```bash
npm install     # 首次克隆后安装依赖
npm run dev     # 本地开发预览（http://localhost:4321，改代码热更新）
npm run data    # 仅重新生成 archives.json（不构建页面）
npm run build   # 生成数据 + 构建静态站点（产物在 dist/）✅ 最常用
npm run preview # 本地预览已构建的 dist/ 产物
```

## 4. 分类目录的显示名

前端显示的「分类名」由 `scripts/build-data.mjs` 顶部的 `CATEGORY_NAMES` 映射：

```js
const CATEGORY_NAMES = {
  '01-foundations': '基础 / 教育',
  '02-ai-skills': 'AI 编程技能',
  '03-ai-agents': 'AI 智能体与应用',
  '04-computer-vision': '计算机视觉',
  '05-dev-tools': '开发工具与框架',
  '06-apps': '应用与娱乐',
  '07-websites': '资源与网站',
};
```

**新增分类时**：① 在 `archive/` 下建新目录（如 `08-xxx`）；② 在 `CATEGORY_NAMES` 里加一行映射；③ 新建的 `.md` 里 `category:` 填目录名。

## 5. 日常维护：新增一个项目

这是最常用的操作。**复制 `_template.md`，填两段内容**：

### 5.0 复制模板

```bash
# 在合适分类下新建文件，文件名一会成为详情页 URL（用英文短横线）
cp archive/_template.md archive/06-apps/my-cool-project.md
```

> 文件名 = 详情页网址 slug，如 `my-cool-project.md` → `/projects/my-cool-project/`。

### 5.1 客观信息（AI 可帮你抓取，勿凭记忆编造）

```yaml
---
name: 项目名称
github: https://github.com/owner/repo
category: 06-apps          # 填 archive/ 下的目录名
tagline: 一句话说明它是干什么的
stack: Go, JavaScript        # 技术栈，逗号分隔
tags: 笔记, Markdown, 本地优先   # 标签，逗号分隔，用于搜索/筛选
status: active              # active/stable/archived/inactive
stars: 4000                 # 验收时的星级快照（可选）
updated: 2026-08-08         # 快照日期
---
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 显示名 |
| `category` | ✅ | 所属分类目录名 |
| `tagline` | ✅ | 一句话定位 |
| `github` | 视类型 | 开源仓库地址；纯网站可留空 |
| `website` | 视类型 | 官网地址；纯网站项目用它 |
| `links` | 聚合条目 | 多链接，格式 `名称\|URL; 名称\|URL` |
| `stack` | 推荐 | 技术栈 |
| `tags` | 推荐 | 标签（决定首页标签筛选） |
| `status` | 推荐 | 维护状态 |
| `stars` / `updated` | 可选 | 快照信息 |

**聚合条目**（一个归档包含多个网站，如「中文技术社区聚合」）：

```yaml
name: 中文技术社区聚合
github:            # 留空
website: https://linux.do/latest   # 主站
links: LINUX DO|https://linux.do/latest; Buzzing|https://www.buzzing.cc/; 编程导航|https://www.codefather.cn/
```

### 5.2 主观信息（AI 无法代写，你来补充）

正文四个小节，用 `## ` 二级标题分隔：

```markdown
# 项目名称

## 它解决什么问题      ← 这个项目解决了什么问题
## 为什么收藏它        ← 你为什么觉得值得存
## 我的笔记            ← 踩坑、用法要点、与其它项目的关联
## 技术栈与状态        ← 技术栈 / 状态 / 链接
```

### 5.3 正文里的 `[[wiki]]` 与链接

- 正文可写 `[[另一个项目名]]`，只要目标项目存在，前端会自动转成跳转它的详情页链接。
- 裸 URL（`https://…`）会被自动转成可点击链接。

### 5.4 本地验证

```bash
npm run build     # 生成数据 + 构建，确认无报错
npm run preview   # 本地预览，检查卡片、详情页、标签是否正常
```

## 6. 日常维护：修改 / 删除项目

- **修改**：直接编辑对应 `.md`，改完 `npm run build`。
- **删除**：删除对应 `.md` 文件，`npm run build`。详情页、卡片、标签统计会自动同步消失。
- **改分类**：改 frontmatter 的 `category:` 字段即可，卡片会自动归位。

## 7. 发布上线（提交并部署）

站点用 GitHub Actions 自动部署，**只要推送到 `main` 分支就会自动构建并发布**。

```bash
git add -A
git commit -m "feat: 新增 xxx 项目"
git push origin main
```

提交后到仓库的 **Actions** 页可看到部署进度，约 1-2 分钟完成，然后刷新线上地址即生效。

> 部署由 `.github/workflows/deploy.yml` 驱动：`npm ci` → `npm run build` → 上传 `dist/` → 发布到 Pages。

## 8. 常见问题

### 8.1 「更多标签…」点不动 / 折叠区不显示
原因：以前用 CSS 类切换，但 `.tagbar[hidden]` 的 `display:none` 优先级更高，盖过了类。
修复：直接切换 `hidden` 属性。若再遇到，检查 `src/pages/index.astro` 里 `#tagMore` 的点击逻辑是否切的是 `tagMoreBox.hidden`。

### 8.2 卡片标题换行后同行卡片中间空白过大
原因：`.card-title h3` 高度不一，`.meta` 用 `margin-top:auto` 推到底部导致不等高。
修复：`.card-title h3` 设 `min-height: 2.6em` + `-webkit-line-clamp: 2`，让标题固定占两行，同行卡片高度一致。

### 8.3 头像不加载 / 构建报远程图片错误
原因：`astro.config.mjs` 的 `image.remotePatterns` 白名单限制远程图片域名。
修复：把图片所在域名加进白名单（如 GitHub 头像需 `github.com` 和 `avatars.githubusercontent.com`）。注意该配置**只允许通配符在域名开头**，子域名要逐个列全。

### 8.4 首屏图片被懒加载（Lighthouse 告警）
原因：首屏 `<img>` 用了 `loading="lazy"`。
修复：首屏卡片（第一个分类前 4 张）用 `eager`，其余保持 `lazy`。逻辑在 `src/pages/index.astro` 的 `loading={ci === 0 && idx < 4 ? 'eager' : 'lazy'}`。

### 8.5 改了 Markdown 但页面没变
先 `npm run build`（它会重新生成 `archives.json`）。如果没运行构建就刷新，页面仍是旧数据。

> 要求：① 用 GitHub API 抓取真实的 name/description/stars/topics；
> ② 按 `archive/_template.md` 格式写 Markdown，放到合适分类目录；
> ③ 客观信息填真实数据，主观小节（为什么收藏/我的笔记）留给我或按公开信息简明填写；
> ④ 运行 `npm run build` 验证通过。
